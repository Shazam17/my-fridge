# Техническое задание: приложение для учёта продуктов, химии и таблеток

Версия: 0.2 (черновик). Изменения 0.2: поля таблеток (дозировка, периодичность), количество предметов, срок годности стал необязательным.

## 1. Общее описание

Мобильное приложение для Android, которое помогает хранить и управлять информацией о предметах домашнего обихода, разделённых по разделам: **продукты**, **химия** (бытовая химия), **таблетки** (лекарства). Приложение позволяет быстро понять, что есть дома, что заканчивается, что скоро испортится, и что нужно докупить.

Версия 1 работает офлайн: данные хранятся в локальном SQLite-файле. Синхронизация выполняется вручную через S3-совместимое хранилище, без собственного бэкенд-сервера (см. `SYNC_SPEC.md`). Все устройства одной семьи (одного `householdId`) работают с общей базой данных приложения: разделы, предметы, комментарии и настройки данных общие для всех членов семьи. Персональных данных отдельных пользователей в v1 нет. Совместные списки в реальном времени в v1 не входят: изменения попадают к остальным участникам при ручной синхронизации.

## 2. Цели и не-цели

**Цели v1**
- Вести разделы и предметы в каждом разделе.
- Отмечать срок годности (опционально), количество (штуки, упаковки), статус «закончился».
- Хранить для таблеток дозировку и периодичность приёма.
- Формировать список покупок из предметов.
- Хранить комментарии к предметам.
- Настраивать иконки для разделов и предметов.
- Скрывать разделы, не удаляя их.

**Не-цели v1**
- Собственный бэкенд-сервер, пользовательские аккаунты, совместное редактирование в реальном времени.
- Распознавание штрихкодов (возможно в v2).
- Напоминания о сроке годности через уведомления (возможно в v2).
- Учёт расхода: автоматическое списание при использовании и история движений. В v1 количество задаётся вручную.

## 3. Термины

| Термин | Значение |
|---|---|
| Раздел | Группа предметов: «Продукты», «Химия», «Таблетки» или пользовательский раздел |
| Предмет (продукт) | Конкретная вещь внутри раздела, например «Молоко», «Средство для посуды», «Парацетамол» |
| Срок годности | Необязательная дата окончания срока годности предмета |
| Количество | Число штук или упаковок предмета дома (опционально) |
| Дозировка | Доза одного приёма, например «500 мг» |
| Периодичность приёма | Как часто принимать, например «2 раза в день» |
| Закончился | Предмет, которого сейчас нет дома (или количество = 0) |
| Список покупок | Выборка предметов, которые нужно купить |
| Комментарий | Текстовая заметка, привязанная к предмету |
| Скрытый раздел | Раздел, который не показывается на главном экране, но сохранён и доступен через настройки |

## 4. Технологический стек

- Язык: Kotlin.
- Платформа: Android, `minSdk = 34`, `targetSdk = 37` (соответствует текущему `app/build.gradle.kts`).
- UI: Jetpack Compose + Material 3.
- Навигация: Navigation Compose.
- Архитектура: MVVM (ViewModel + StateFlow), однонаправленный поток данных, слои UI / domain / data.
- Хранение: SQLite-файл `inventory.db` (Room поверх SQLite или прямой SQLite). Миграции через версионирование схемы.
- Асинхронность: Kotlin Coroutines и Flow.
- DI: Hilt или ручная инъекция через `AppContainer` (решение за разработчиком, но одно на весь проект).
- Иконки: набор Material Symbols, встроенный в приложение (без загрузки из сети).
- Тесты: JUnit + MockK для ViewModel и use case, Room in-memory для DAO, Compose UI test для ключевых сценариев.

Примечание: текущий проект создан на XML/View (шаблон). Для Compose нужно подключить соответствующие зависимости и плагин, либо создать новый модуль.

## 5. Модель данных

### 5.1. Сущности

**Section (раздел)**

| Поле | Тип | Описание |
|---|---|---|
| id | Long (PK, auto) | Идентификатор |
| name | String, 1–50 симв. | Название, уникально среди разделов без учёта регистра |
| iconKey | String | Ключ иконки из встроенного набора |
| sortOrder | Int | Порядок отображения |
| isHidden | Boolean, default false | Скрыт ли раздел |
| isSystem | Boolean | Признак предустановленного раздела (продукты, химия, таблетки). Переименовывать можно, удалять — нет (см. раздел 7.4) |
| createdAt | Instant | Дата создания |

**Product (предмет)**

| Поле | Тип | Описание |
|---|---|---|
| id | Long (PK, auto) | Идентификатор |
| name | String, 1–100 симв. | Название |
| sectionId | Long (FK → Section) | Раздел. При удалении раздела предметы удаляются вместе с ним (CASCADE) |
| iconKey | String? | Иконка предмета. Если null, используется иконка раздела |
| expiresAt | LocalDate? | Срок годности. Необязательное поле, null = не указан |
| isOutOfStock | Boolean, default false | Закончился |
| quantity | Int?, 0–9999 | Количество. null = не учитывается |
| unit | String?, enum | Единица: «шт.», «упаковка», «флакон», «пачка», «тюбик», «бутылка», «кг», «л». По умолчанию «шт.», если задан quantity. Количество целое (дробные значения не поддерживаются) |
| dosage | String?, 1–50 симв. | Дозировка, например «500 мг», «10 мл» |
| intakeFrequency | String?, 1–100 симв. | Периодичность приёма, например «2 раза в день», «каждые 8 часов», «по необходимости» |
| isInShoppingList | Boolean, default false | Находится в списке покупок |
| createdAt | Instant | Дата создания |
| updatedAt | Instant | Дата последнего изменения |

**Comment (комментарий)**

| Поле | Тип | Описание |
|---|---|---|
| id | Long (PK, auto) | Идентификатор |
| productId | Long (FK → Product) | Предмет. При удалении предмета комментарии удаляются (CASCADE) |
| text | String, 1–1000 симв. | Текст |
| createdAt | Instant | Дата создания |

Правила полей Product:
- Признак «портящийся» отдельным полем не хранится. Предмет со сроком годности: `expiresAt != null`.
- Если `quantity = 0`, то `isOutOfStock = true`. Переход `quantity` из 0 в значение больше 0 снимает `isOutOfStock`. Ручная пометка «закончился» при заданном `quantity` ставит `quantity = 0`.
- `unit` имеет смысл только вместе с `quantity`.
- `dosage` и `intakeFrequency` доступны в любом разделе; в разделе «Таблетки» поля показываются первыми в форме.

### 5.2. Связи
- Section 1 — N Product.
- Product 1 — N Comment.

### 5.3. Индексы
- `Product(sectionId)`, `Product(isInShoppingList)`, `Product(expiresAt)`, `Comment(productId)`.

### 5.4. Предустановленные данные
При первом запуске создаются три раздела: «Продукты» (`food`), «Химия» (`chemistry`), «Таблетки» (`pills`). Все `isSystem = true`.

## 6. Иконки

- Встроенный набор: не менее 60 иконок, сгруппированных по категориям (еда, напитки, уборка, гигиена, лекарства, прочее).
- Раздел и предмет используют иконку по `iconKey`.
- Для предмета иконка необязательна; если не выбрана, показывается иконка раздела.
- Выбор иконки: сетка с поиском по названию иконки.

## 8. Подтверждения и сообщения

| Действие | Диалог |
|---|---|
| Удаление раздела | Предупреждение: «Удалить раздел „X“? Вместе с ним будут удалены N предметов и все их комментарии. Это действие нельзя отменить.» Кнопки: «Отмена» / «Удалить». Если в разделе больше 0 предметов, требуется второе подтверждение: ввести название раздела или нажать «Да, удалить всё» |
| Удаление предмета | «Удалить предмет „X“? Комментарии к нему тоже будут удалены.» |
| Удаление комментария | «Удалить комментарий?» |
| Очистка списка покупок | «Очистить список покупок? Предметы останутся в разделах.» |
| Перенос предмета в раздел, где уже есть предмет с таким же названием | Предупреждение о дубликате, возможность отмены |

Скрытие раздела подтверждения не требует (обратимое действие), вместо этого показывается Snackbar «Раздел скрыт» с кнопкой «Отменить».

## 9. Экраны и навигация

1. **Главный экран (Разделы)**: список видимых разделов с иконкой, названием и количеством предметов. Кнопка «+» — создать раздел. Нижняя навигация: «Разделы», «Список покупок», «Настройки».
2. **Раздел**: список предметов с пометками (закончился, количество, срок). Кнопка «+» — добавить предмет. Меню раздела: переименовать, сменить иконку, скрыть, удалить.
3. **Предмет (карточка)**: название, иконка, раздел, количество, срок годности (если задан), статус «закончился», для таблеток дозировка и периодичность приёма, флаг «в списке покупок», список комментариев, поле ввода нового комментария. Действия: редактировать, перенести в раздел, удалить.
4. **Добавление / редактирование предмета**: форма (см. FR-P2).
5. **Создание / редактирование раздела**: название и выбор иконки.
6. **Выбор иконки**: сетка с категориями и поиском.
7. **Список покупок**: группировка по разделам, чекбоксы «куплено».
8. **Скрытые разделы**: список с кнопкой «Показать».
9. **Настройки**: скрытые разделы, о приложении. (Тема — в S.)

Навигация: Главный → Раздел → Предмет → (Редактирование). Список покупок и Настройки — отдельные вкладки.

## 10. Нефункциональные требования

- **Офлайн-first**: все функции работают без интернета. Сеть нужна только для кнопки «Синхронизировать» (разрешение `INTERNET`).
- **Производительность**: открытие раздела с 500 предметами < 300 мс; запись в БД выполняется вне главного потока.
- **Целостность данных**: все операции, затрагивающие несколько таблиц (удаление раздела, очистка списка), выполняются в одной транзакции Room.
- **Надёжность**: при сбое записи пользователь видит сообщение об ошибке, данные не теряются частично.
- **Доступность**: `contentDescription` у всех иконок, минимальный размер касаемой области 48dp, поддержка TalkBack.
- **Локализация**: интерфейс на русском языке; строки вынесены в `strings.xml`.
- **Тема**: Material 3, светлая и тёмная темы по системной настройке, динамические цвета (Android 12+).
- **Резервное копирование**: основной механизм — синхронизация через S3 (`SYNC_SPEC.md`). Auto Backup Google исключает файл БД и ключи S3 (`backup_rules.xml`, `data_extraction_rules.xml`).
- **Логи**: в release-сборке без вывода пользовательских данных.

## 11. Ограничения и валидация

- Название раздела и предмета: не пустое после `trim()`, до 50 и 100 символов соответственно.
- Текст комментария: не пустой, до 1000 символов.
- Количество: целое от 0 до 9999. Дозировка до 50 символов, периодичность приёма до 100 символов; если заполнены, не пустые после `trim()`.
- Срок годности (опционально): дата не раньше сегодняшней при создании (допускается ввод прошедшей даты при редактировании уже существующего предмета).
- Имена разделов уникальны (без учёта регистра).
- Имена предметов внутри одного раздела предупреждают о дубликатах, но не запрещают их.

## 12. Пользовательские сценарии

Формат: цель, предусловия, основной сценарий, альтернативные и ошибочные ветки.

### Сценарий 1. Первый запуск
- **Предусловие:** приложение установлено, БД пуста.
- **Основной ход:** приложение создаёт три системных раздела («Продукты», «Химия», «Таблетки»). Пользователь видит главный экран с этими разделами и пустыми счётчиками.

### Сценарий 2. Создание пользовательского раздела
- **Цель:** завести раздел, например «Косметика».
- **Основной ход:**
  1. Пользователь нажимает «+» на главном экране.
  2. Вводит название «Косметика».
  3. Выбирает иконку из сетки.
  4. Нажимает «Сохранить». Раздел появляется в списке.
- **Ошибки:** пустое название → подсказка «Введите название»; название уже существует → «Раздел с таким названием уже есть».

### Сценарий 3. Добавление предмета в раздел
- **Цель:** добавить «Молоко» в раздел «Продукты» с количеством и сроком годности.
- **Основной ход:**
  1. Пользователь открывает раздел «Продукты».
  2. Нажимает «+».
  3. Вводит «Молоко», выбирает иконку молока (необязательно).
  4. Указывает количество «2 шт.». Включает переключатель «Срок годности» и выбирает дату: 10 дней от сегодня.
  5. Сохраняет. Предмет появляется в списке с пометкой срока.
- **Альтернатива:** предмет без срока годности (переключатель выключен) — пометка срока не показывается.

### Сценарий 4. Добавление предмета с выбором другого раздела
- **Цель:** добавить «Парацетамол» в «Таблетки», находясь на главном экране.
- **Основной ход:** «+» на главном экране → предмет → выбор раздела «Таблетки» → сохранение.

### Сценарий 5. Перенос предмета в другой раздел
- **Цель:** переместить «Средство для посуды» из «Продуктов» в «Химию» по ошибке.
- **Основной ход:**
  1. Открывает карточку предмета.
  2. Меню → «Перенести в раздел».
  3. Выбирает «Химия».
  4. Предмет исчезает из «Продуктов» и появляется в «Химии». Комментарии и флаги сохраняются.
- **Ошибка:** в целевом разделе уже есть предмет с таким названием → предупреждение, пользователь подтверждает или отменяет.

### Сценарий 6. Пометка предмета как портящийся
- **Цель:** задать срок годности уже существующему предмету.
- **Основной ход:** карточка предмета → «Редактировать» → включить «Срок годности» → выбрать дату → «Сохранить». Срок отображается на карточке и в списке раздела.
- **Сценарий в процессе:** срок истекает через 3 дня → предмет подсвечивается жёлтым. Срок прошёл → красным.

### Сценарий 7. Пометка предмета как закончившийся
- **Цель:** отметить, что заканчивается «Парацетамол».
- **Основной ход:** в списке раздела свайп или кнопка «Закончился» → предмет перемещается в блок «Закончились» вверху (или внизу, по настройке) и получает метку.
- **Отмена:** повторное действие снимает метку. Если задано количество, пометка ставит 0, снятие ставит 1.

### Сценарий 8. Добавление предмета в список покупок
- **Цель:** добавить «Молоко» в список покупок.
- **Основной ход:**
  1. Из карточки предмета или из списка, через меню, выбирает «В список покупок».
  2. Открывает вкладку «Список покупок» и видит предмет в группе «Продукты».
- **Альтернатива:** из списка «закончившихся» выбирает несколько предметов сразу и добавляет их в список покупок (S).

### Сценарий 9. Покупка предмета из списка покупок
- **Основной ход:** на вкладке «Список покупок» отмечает чекбокс «Куплено». Предмет исчезает из списка, флаг «закончился» снимается.

### Сценарий 10. Удаление предмета
- **Основной ход:** карточка предмета → «Удалить» → подтверждение → предмет и его комментарии удалены.
- **Отмена:** в диалоге «Отмена», ничего не происходит.

### Сценарий 11. Удаление раздела с подтверждением
- **Цель:** удалить раздел «Косметика», в котором 12 предметов.
- **Основной ход:**
  1. В меню раздела выбирает «Удалить раздел».
  2. Первый диалог: «Удалить раздел „Косметика“? Будут удалены 12 предметов и все их комментарии. Действие необратимо.» → «Далее».
  3. Второй диалог: пользователь вводит название раздела «Косметика» для подтверждения → «Удалить».
  4. Раздел и все его данные удалены, пользователь возвращается на главный экран.
- **Для пустого раздела:** один диалог «Удалить пустой раздел „X“?».
- **Для системного раздела:** пункт «Удалить» недоступен; доступно «Скрыть».

### Сценарий 12. Скрытие раздела
- **Цель:** убрать с глаз раздел «Таблетки», которым пользователь временно не пользуется.
- **Основной ход:** меню раздела → «Скрыть» → раздел исчезает с главного экрана, появляется Snackbar «Раздел скрыт» с кнопкой «Отменить».
- **Возврат:** Настройки → «Скрытые разделы» → «Показать» у нужного раздела.
- **Важно:** предметы скрытого раздела не попадают в список покупок и не участвуют в поиске, если пользователь не включил показ скрытых (S).

### Сценарий 13. Выбор иконки для раздела
- **Основной ход:** меню раздела → «Изменить» → нажимает на текущую иконку → экран выбора иконки → выбирает новую → «Сохранить». Иконка меняется на главном экране.

### Сценарий 14. Выбор иконки для предмета
- **Основной ход:** в форме предмета нажимает на иконку → выбирает из сетки → сохраняет. Если иконка не выбрана, отображается иконка раздела.
- **Сброс:** кнопка «Сбросить иконку» возвращает иконку раздела.

### Сценарий 15. Добавление комментария к предмету
- **Цель:** записать «Купить без лактозы, брать у дома».
- **Основной ход:** карточка предмета → поле «Добавить комментарий» → ввод текста → «Отправить». Комментарий появляется первым в списке с датой.
- **Ошибка:** пустой текст → кнопка «Отправить» неактивна.

### Сценарий 16. Просмотр комментария
- **Цель:** посмотреть, что написано к предмету.
- **Основной ход:** в списке раздела нажимает на предмет → открывается карточка → видно все комментарии. На списке у предмета с комментариями есть индикатор (S).

### Сценарий 17. Удаление комментария
- **Основной ход:** карточка предмета → долгое нажатие или «⋮» у комментария → «Удалить» → подтверждение → комментарий удалён.

### Сценарий 18. Редактирование комментария (S)
- **Основной ход:** «⋮» у комментария → «Изменить» → правка текста → «Сохранить». Дата обновления отображается как «изменено».

### Сценарий 19. Поиск предмета (S)
- **Основной ход:** на главном экране нажимает иконку поиска → вводит «моло» → видит «Молоко» из раздела «Продукты». Нажатие открывает карточку.
- **Примечание:** скрытые разделы в поиске не участвуют.

### Сценарий 20. Фильтр предметов (S)
- **Основной ход:** в разделе выбирает фильтр «Со сроком годности» → видны только предметы с `expiresAt != null`, отсортированные по сроку.

### Сценарий 21. Работа без интернета
- **Основной ход:** пользователь в авиарежиме выполняет все сценарии 2–19. Все операции работают, данные сохраняются локально.

### Сценарий 22. Восстановление после переустановки (M, если включён Auto Backup)
- **Основной ход:** пользователь восстанавливает приложение из облачного бэкапа Google. Разделы, предметы и комментарии восстанавливаются.
- **Ограничение:** бэкап зависит от настроек Google и не гарантирует восстановления; в интерфейсе не обещается.

### Сценарий 23. Добавление таблетки с дозировкой и периодичностью
- **Цель:** завести «Парацетамол» с дозировкой и схемой приёма.
- **Основной ход:**
  1. Пользователь открывает раздел «Таблетки» и нажимает «+».
  2. Вводит «Парацетамол», в поле «Дозировка» — «500 мг», в поле «Периодичность приёма» — «по необходимости».
  3. Указывает количество «1» и единицу «упаковка».
  4. Срок годности не указывает (переключатель выключен) → «Сохранить».
- **Ошибки:** дозировка длиннее 50 символов → подсказка о лимите.

### Сценарий 24. Учёт количества
- **Цель:** отслеживать остаток, например «Молоко: 2 шт.».
- **Основной ход:** карточка предмета → кнопка «−» уменьшает количество. При 0 предмет получает статус «закончился» и попадает в блок «Закончились».
- **Альтернатива:** при количестве 1 и больше статус «закончился» снимается автоматически.
- **Ошибка:** количество не может быть меньше 0 (кнопка «−» неактивна).

## 14. План работ (ориентировочно)

1. **Этап 1 — основа:** подключение Compose, Room, навигации; модель данных и DAO; предустановленные разделы. Тесты DAO.
2. **Этап 2 — разделы:** список, создание, редактирование, скрытие, удаление с подтверждениями. Выбор иконки.
3. **Этап 3 — предметы:** список, добавление, редактирование, перенос, срок годности, количество, статус «закончился», удаление, дозировка и периодичность для таблеток.
4. **Этап 4 — список покупок.**
5. **Этап 5 — комментарии.**
6. **Этап 6 — S-функции:** поиск, фильтры, индикация сроков, порядок разделов.
7. **Этап 7 — стабилизация:** UI-тесты ключевых сценариев, проверка доступности, тёмная тема, подготовка релиза.
